## RM-01 플레이어 자막 오버레이·이중 자막

### 목표

- 기존 자막(DOM 행, `caption_list.xml`→VTT, 미디어 스크립트)을 플레이어 위에 직접 표시합니다.
- 원문 아래에 번역 자막(기본 한→영, 반대 방향 선택 가능)을 함께 표시합니다. 교환학생이 주 대상입니다.
- 글자 크기, 위치, 배경 투명도, 원문/번역 표시 여부를 사용자가 조절합니다.

### 설계 메모

- 자막 획득은 `src/captions/service.ts`의 `detectCaptions`를 재사용합니다.
- 표시 위치는 kucom 플레이어 프레임(`https://kucom.korea.ac.kr/em/*`)입니다. 현재 `entrypoints/player.content.ts`는 재생 기능 전용이라 `UNIDOCK_PLAYBACK=1` 빌드에만 들어갑니다. 오버레이는 **재생 제어 코드와 분리된 별도 content script**로 만들어 release 빌드에 포함합니다(`playback/*` import 금지 규칙은 유지).
- 동기화는 `video.currentTime`을 읽어 `timeupdate`/`requestVideoFrameCallback`으로 현재 cue를 찾습니다. `<track>` 주입보다 직접 렌더링한 오버레이가 스타일 제어와 이중 자막에 유리합니다.
- 전체화면에서도 보이도록 플레이어 컨테이너(전체화면 대상 요소) 안에 오버레이를 붙입니다.
- 번역 엔진 후보:
  1. Chrome 내장 Translator API(기기 내, Chrome 138+). 지원 여부를 감지해서 우선 사용합니다.
  2. 서버 번역(LLM/번역 API). 영상 단위로 결과를 캐시해 재사용합니다(자막 생성 서버와 같은 캐시 구조).
- 번역은 cue 단위 대신 문장 단위로 묶어 처리한 뒤 다시 타임스탬프에 나눠 붙여야 품질이 나옵니다.

### 열린 질문

- 플레이어 DOM 구조와 전체화면 요소가 무엇인지(실제 LMS에서 확인 필요).
- 자막이 없는 영상은 STT 자막 생성 기능(백로그 BL-01)에 의존합니다.

## RM-02 자막 탭 개편 (전 과목 자막 검색)

### 목표

- 현재 "자막 추출" 탭(`entrypoints/sidepanel/CaptionsPanel.tsx`)을 **"자막" 탭**으로 바꿉니다. 지금처럼 "열린 플레이어에서 감지 → 다운로드"하는 일회성 도구가 아니라, 수강 과목의 강의 자막을 모아 보고 검색하는 곳으로 만듭니다.
- 범위는 이미 API로 받아오는 녹화 강의 목록(`RECORDINGS_LIST`)에 한정합니다. 목록에 있는 강의만 자막을 조회합니다.
- 키워드로 전 과목 자막을 검색하고, 결과를 누르면 해당 영상을 열어 그 시점으로 이동합니다.

### UX 흐름

```
자막 탭
├─ 상단: 전 과목 검색창  ("정규화", "시험 범위" …)
│    └─ 결과: 과목 · 주차/강의명 · 타임스탬프 · 앞뒤 문맥 → 클릭 시 영상 열기 + 시점 이동
├─ 과목 필터 칩 (전체 / 과목별)
├─ 강의 목록 (주차순)
│    ├─ 상태 배지: 공식 자막 있음 · 자막 없음(→ STT 생성 요청, BL-01) · 수집 중 · 실패
│    └─ 강의 선택 → 자막 뷰어
│         ├─ 강의 내 검색(일치 구간 강조, 이전/다음 이동)
│         ├─ 타임스탬프 클릭 → 해당 시점으로 영상 열기
│         ├─ 번역 자막 토글(RM-01 번역 재사용)
│         └─ 내보내기: TXT / SRT / VTT / JSON (기존 captions/download.ts 확장)
└─ "지금 보는 강의" 카드
     └─ 플레이어가 열린 탭이면 자동 감지 → 자막 뷰어가 재생 위치를 따라 스크롤(RM-01 오버레이와 같은 동기화 소스)
```

- 기존 "자막 감지" 버튼 흐름은 "지금 보는 강의" 카드로 흡수합니다. 목록에 없는 영상(공개 영상 등)도 여기서 계속 지원합니다.
- 첫 진입 시 자막 수집이 백그라운드로 진행되며, 진행률(`n / 전체 강의`)을 표시합니다. 수집이 끝나지 않아도 이미 받은 자막부터 검색됩니다.

### 데이터 경로

플레이어를 열지 않고 자막을 받는 경로가 공개 샘플(`scripts/test-caption-live.mjs`의 KU 교육 영상)로 확인되었습니다.

```
Canvas 모듈 항목(ExternalTool)        ← 이미 수집 중
   └─ ? → kucom content_id            ← 미확인 (아래 열린 질문)
        └─ GET kucom /viewer/ssplayer/uniplayer_support/content.php?content_id=…
             └─ content_uri, content_duration, main_media(진행형 mp4), 제목
                  └─ GET {content_uri}caption_list.xml → .vtt
```

2026-10-09 공개 샘플 확인 결과:

- `content.php`는 로그인 없이 XML을 반환합니다. 여기에 `content_uri`, 재생 시간, 썸네일, 미디어 주소가 들어 있습니다.
- `{content_uri}caption_list.xml`과 그 안의 `.vtt`도 로그인 없이 받아집니다.
- 미디어는 DRM 없는 진행형 mp4이고 `accept-ranges: bytes`를 지원합니다(NCloud CDN). Referer 없이는 403, kucom 플레이어 Referer가 있으면 200입니다. 이 결과는 BL-01(STT) 오디오 확보에도 그대로 쓰입니다.
- `content.php`는 메타데이터 조회일 뿐 플레이어 실행이 아니라서 시청 기록이나 출석 집계에 잡히지 않을 가능성이 높습니다. 다만 실제 LMS에서 확인이 필요합니다.

### 설계 메모

- 녹화 목록은 기존 `RECORDINGS_LIST` 수집(`src/api/recording-collection.ts`)을 재사용하고, 항목마다 content_id를 붙이는 단계를 추가합니다.
- 자막 파싱은 기존 `src/captions/extract.ts`의 XML→VTT 선택 로직(한국어 우선)과 `parseVtt`를 재사용합니다. 플레이어 프레임의 `uniPlayerConfig` 대신 `content.php` XML에서 같은 값을 읽도록 입력부만 분리합니다.
- 자막 인덱스는 로컬(IndexedDB)에 저장하고 content_id를 키로 씁니다. 영상이 바뀌지 않는 한 다시 받을 필요가 없으므로, 새로 생긴 강의만 증분 수집합니다. 한국어는 형태소 분석 없이도 문자 2-gram 인덱스로 충분히 검색됩니다.
- 시점 이동은 기존 `RECORDING_OPEN` 핸들 흐름(`src/navigation-catalog.ts`)으로 영상을 연 뒤, player content script가 `video.currentTime`을 설정합니다.
- 수집 동시성은 3개, 요청 간격과 전체 수에 상한을 둡니다.

### 열린 질문

- **Canvas 모듈 항목 → kucom content_id 매핑.** 로그인된 LMS에서 확인할 후보 경로:
  1. LearningX 강의 콘텐츠 목록 API(`/learningx/api/v1/courses/{courseId}/…`, 게시판 API와 같은 `xn_api_token` 사용). 과목 전체의 content_id를 한 번에 받을 수 있으면 가장 좋습니다.
  2. 모듈 항목의 외부 도구 URL(`/learningx/redirect/courses/{courseId}/external_tools/{toolId}` 등)을 따라가 응답에서 `kucom.korea.ac.kr/em/{content_id}`를 찾는 방법. LTI 실행이 시청 기록에 잡히는지 확인해야 합니다.
- 실제 수강 강의의 `content.php`·자막·미디어도 공개 샘플처럼 로그인 없이 열리는지(강의별 공개 설정 차이 가능).
- 자막이 없는 강의 비율. 높다면 BL-01(STT) 우선순위를 올립니다.

## RM-03 마감 알림 (외부 메신저·이메일)

### 목표

- 마감 D-3, D-1, 3시간 전에 사용자가 고른 채널로 과제 마감을 알립니다. 시점은 설정에서 켜고 끌 수 있습니다.
- 이미 제출한 과제는 알리지 않습니다.
- 브라우저 알림(Chrome `notifications`)은 쓰지 않습니다. 브라우저가 꺼져 있어도 알림이 가야 하기 때문입니다.

### 지원 채널

| 채널     | 등급 | 연결 방식                                                      | 메모                                                                       |
| -------- | ---- | -------------------------------------------------------------- | -------------------------------------------------------------------------- |
| Discord  | 무료 | 사용자가 채널 Webhook URL 입력, 또는 uniDock 봇 DM             | Webhook이 가장 간단. 봇 DM은 서버 공유 필요                                |
| Telegram | 무료 | uniDock 봇에 `/start <연결 코드>` 전송 → 서버가 `chat_id` 저장 | 봇 토큰은 서버에만 둠                                                      |
| Slack    | 무료 | Incoming Webhook URL 입력(1차), 이후 Slack 앱 OAuth            | 워크스페이스 정책상 Webhook 생성이 막힌 경우 앱 설치 필요                  |
| 이메일   | 무료 | 주소 입력 → 확인 메일 링크로 인증                              | 발송은 Resend/SES 등. 인증 안 된 주소로는 발송 금지(스팸 악용 방지)        |
| 카카오톡 | 유료 | 전화번호 입력 → 인증 → 알림톡 발송(Solapi 등 대행사 경유)      | 건당 비용 발생, 비즈니스 채널·템플릿 사전 심사 필요. 그래서 유료 플랜 전용 |

### 구조

```
확장(서비스 워커)                         uniDock 알림 서버
  ├─ chrome.alarms로 주기 수집(예: 1시간)
  ├─ Canvas GET → 마감 목록 투영
  └─ POST /v1/deadlines (스냅샷) ─────▶  스냅샷 저장(사용자별 전체 교체)
                                           ├─ 알림 시각 계산(D-3, D-1, 3시간 전)
                                           ├─ 스케줄러가 시각 도래 시 발송 큐에 적재
                                           └─ 채널별 발송 워커(Discord/Telegram/Slack/메일/알림톡)
```

- **발송은 서버가 합니다.** 확장이 직접 Webhook을 호출하면 브라우저가 꺼져 있을 때 알림이 가지 않고, Telegram 봇 토큰이나 메일·알림톡 API 키를 확장에 넣을 수 없습니다.
- **수집은 확장이 합니다.** 서버는 LMS 세션이 없고, SSO 쿠키를 서버로 넘기는 구조는 만들지 않습니다. 확장이 로그인된 세션으로 수집해서 스냅샷만 올립니다.
- 수집 로직은 `DEADLINES_LIST`/`TODO_LIST` 투영(`src/domain-items.ts`)을 재사용하되, 사이드패널→content script 경로가 아니라 **서비스 워커에서 직접 Canvas GET**을 호출하는 경로가 새로 필요합니다(host permission으로 쿠키 포함 요청 가능). 사이드패널을 열 때도 즉시 한 번 동기화합니다.
- 스냅샷 필드: 과제 키(서버 저장용 해시), 과목명, 과제명, 마감 시각, 제출 여부, 과제 링크. 서버는 스냅샷을 통째로 교체하므로 삭제·연장·제출이 다음 동기화 때 반영됩니다.
- 중복 방지: 서버가 `(사용자, 과제 키, 알림 단계)`로 발송 기록을 남깁니다. 마감 시각이 바뀌면 해당 과제의 기록을 초기화합니다.
- 사용자 식별: 확장 설치 시 발급한 계정 토큰(익명 계정)으로 시작하고, 유료 플랜 결제 시점에 이메일 계정과 연결합니다.
- 메시지 형식: `[D-1] 자료구조 · 과제 3 — 10/10(금) 23:59 마감` + 과제 링크. 같은 시각에 여러 개면 한 메시지로 묶습니다.
- 발송 실패(Webhook 삭제, 봇 차단 등)가 연속되면 채널을 비활성화하고 다른 채널이나 사이드패널에 안내합니다.
- 액션 아이콘 배지(`chrome.action.setBadgeText`)에 24시간 내 마감 수를 함께 표시합니다(권한 불필요).

### 알려진 한계

- 브라우저가 오래 꺼져 있으면 새로 올라온 과제는 서버가 모릅니다. 이미 동기화된 마감 알림은 정상 발송됩니다.
- 브라우저가 꺼진 동안 제출한 과제는 서버가 미제출로 알고 있어서 알림이 갈 수 있습니다. 메시지에 "마지막 동기화: n시간 전"을 표시해 오해를 줄입니다.
- 연속 수집 실패(`LOGIN_REQUIRED`)가 일정 시간 이어지면 "LMS에 다시 로그인해야 마감 정보가 갱신됨" 메시지를 한 번 보냅니다.

### 열린 질문

- 서비스 워커에서의 Canvas 요청이 SSO 세션 쿠키를 정상적으로 싣는지(SameSite 설정에 따라 다를 수 있음) 실제 LMS에서 확인 필요.
- 유료 플랜 범위: 카카오톡 외에 무엇을 묶을지(알림 시점 커스터마이즈, BL-01 STT 우선 처리 등)와 결제 수단.
- 카카오 알림톡 대행사 선정과 템플릿 심사 일정.

## 정책 변경 체크리스트 (착수 전)

현재 문서의 다음 문구가 위 기능과 충돌합니다. 기능별로 범위를 좁혀 수정합니다.

- [ ] `AGENTS.md` ANTI-PATTERNS: `alarms`는 playback 빌드 전용 → 마감 수집용으로 release 포함.
- [ ] `AGENTS.md`/`SECURITY-REVIEW.md`: 마감 스냅샷(과목명·과제명·마감 시각·제출 여부)이 uniDock 알림 서버로 전송됨을 명시. `wxt.config.ts` CSP `connect-src`에 알림 서버 출처 추가.
- [ ] `AGENTS.md`/`src/AGENTS.md`: "LMS 응답·식별자를 저장하지 않음" → 자막 검색 인덱스와 알림 계정 토큰·채널 설정 예외 명시.
- [ ] `src/AGENTS.md`/`SECURITY-REVIEW.md`: "seek 없음" → 사용자 클릭에 의한 시점 이동만 허용(자동 재생·진도 조작은 계속 금지).
