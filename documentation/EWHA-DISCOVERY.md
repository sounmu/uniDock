# 이화여대 연동 조사와 사용자 확인표

2026-11-02 작성. 저장소 문서와 일부 핵심 코드의 정적 조사 결과이며 실제 LMS 검증 결과가 아니다.
이화여대의 LMS 제품, 도메인, API, 플레이어는 아직 미확인이다.
설계 원칙은 [다중 대학 지원](MULTI-UNIVERSITY.md)을 따른다.

## 현재 기능과 사용자가 확인할 사항

아래 각 행의 마지막 칸을 채운다. 기능마다 접근 경로, 실제 사례, 동작 후 결과와
상태의 의미를 적는다. 개인정보 대신 구분 가능한 별칭을 쓴다.
확인하지 못하면 `미확인: 사유`, 화면에 없다면 `찾지 못함`으로 기록한다.
API 존재 여부나 구현 가능성은 사용자가 판단할 필요가 없다.

E12의 영상 종료와 LMS 출석 인정은 별개다. 출석 표시가 있으면 위치와 의미를 기록하되
영상 종료만으로 출석 성공이라 판단하지 않는다.
현재 남은 과제 후보는 미래 마감·잠기지 않음·미제출 조건으로 계산되며 실제 제출 가능 보장은 아니다.

기능별 상세 기록이 필요하면 다음 양식을 복제한다.

```text
기능 ID:
화면 이름 / 접근 경로:
사례 별칭:
사용자 동작:
정상 결과와 상태 표시의 의미:
예외 사례:
확인하지 못한 부분:
```

비밀번호, 쿠키, 토큰, 원본 HAR, 개인정보가 있는 화면을 저장소에 넣지 않는다.
개발 측이 화면 의미를 확인한 뒤 필요한 비식별 자료만 별도로 지정한다.

## 학교와 독립적으로 유지할 기능

설정, 선택적 통계 동의·철회, 로컬 데이터 삭제, 업데이트 안내, 목록 페이지 이동,
보기 설정과 다운로드 상태 UI는 공통 앱 영역으로 유지할 후보다.
AI 자막 서버 Google 로그인, 사용량 안내, 업로드·작업 상태·복구 UI도 공통 후보이며
학교 로그인과 혼동하지 않는다. 이 항목들은 학교별 자료 수집보다 개발 측 회귀 검증 대상이다.

충돌하는지는 아직 코드 전체를 추적하지 않았다. 이 문서는 전수 코드 감사가 아니다.

## 범위와 다음 결정

현재 기능 전체의 이식이 목표다. 일반 과제 제출, 글쓰기·댓글·수강 변경은 현재 기능이 아니다.
공지·게시판은 자료/영상 수집 및 일정 표시에서 사용되며, 독립적인 공지 본문 리더가
구현돼 있다고 간주하지 않는다. Files 탭 전체 수집과 외부 저장소도 README상 범위 밖이다.

1. 사용자가 E01~E16의 실제 화면과 사례를 채운다.
2. 개발 측이 해당 사례의 API·응답·플레이어를 분석한다.
3. 두 학교의 데이터 의미를 비교해 공통 계약과 학교/LMS/플레이어 경계를 확정한다.
4. 기능 단위로 고려대 동작을 보존하며 이화여대 연동과 계약 테스트를 추가한다.

API가 같다는 전제로 호스트만 추가하거나, 이화여대 자료 없이 모든 인터페이스를 먼저
확정하지 않는다. `unidock-captions`는 실제 입력·식별자 차이가 확인되기 전에는 변경하지 않는다.
